\title{脆弱性検知条件の供給源の再検討 \\ ---検知精度によるNVD・VulnCheck・一次データソースの比較とLLMによる構造化---}
\etitle{Revisiting the Supply of Vulnerability Detection Conditions: Comparing NVD, VulnCheck and Primary Sources by Detection Accuracy, with LLM-assisted Structuring}

\begin{abstract}
我々はOSS脆弱性スキャナVulsと脆弱性DBを運用している．
CVE急増を受け，検知に不可欠な「どの製品のどの版が影響を受けるか」の供給源を調べた．
NVD・VulnCheck NVD++の全件（取下げ除き353,704件）では，NVDのCPE適用条件の付与率が2023年以前の100\%から2026年56.1\%へ低下し，2025年分の37.3\%はNVD自身が解析対象外と明示していた．
ただし付与率は検知精度を予測しない．
データソースのみを変えたDBで10環境を検知すると，NVDのみの未検知率はWindows Server 2022の1.3\%からサポート終了版FortiOSの68.8\%まで開き，その93.5\%は組込みOSS部品であった．
macOSでは下限を持たないCPEにより過剰検知が81.5\%に達した．
VulnCheckはEdgeの未検知を96.2\%から0.4\%へ下げる一方，Windowsでは過剰検知率70.6\%を生み，独自CPEは日単位で入れ替わる．
一次データソースが常に優るとは限らない．供給源の選択は製品ごとに異なる．
本稿はその判断に要る測定と，一次データソースをLLMで構造化する方式を示す．
\end{abstract}

\begin{eabstract}
We develop Vuls, an open-source vulnerability scanner, and its database.
Given the CVE surge, we ask where a scanner should get its detection conditions.
Across all 353,704 non-rejected entries, NVD's CPE coverage fell from 100\% through 2023 to 56.1\% in 2026, with 37.3\% of 2025 entries marked Deferred.
Coverage, however, does not predict detection accuracy.
Across ten environments differing only in input source, NVD's miss rate ranges from 1.3\% on Windows Server 2022 to 68.8\% on an end-of-life FortiOS, 93.5\% of the latter embedded OSS components.
How it errs differs too: on macOS, CPEs unbounded below drive an 81.5\% false-positive rate.
VulnCheck cuts Edge's miss rate from 96.2\% to 0.4\%, yields 70.6\% false positives on Windows, and rewrites its own CPEs daily.
Nor is the primary source always better; the choice differs by product.
We report the measurements that decision needs and a reproducible LLM-assisted method for structuring primary sources.
\end{eabstract}
