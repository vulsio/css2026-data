\title{脆弱性検知条件の供給源の再検討 \\ ---検知精度によるNVD・VulnCheck・一次データソースの比較とLLMによる構造化---}
\etitle{Revisiting the Supply of Vulnerability Detection Conditions: Comparing NVD, VulnCheck and Primary Sources by Detection Accuracy, with LLM-assisted Structuring}

\affiliate{FUTURE}{フューチャー株式会社\\
Future Corporation}

\begin{abstract}
我々はOSS脆弱性スキャナVulsと脆弱性DBを開発・運用している．
CVE報告件数の急増を受け，検知に不可欠な「どの製品のどの版が影響を受けるか」という条件をどの供給源から得るべきかを調べた．
NVDとVulnCheck NVD++の全件（取下げ除き353,704件）では，NVDによるCPE適用条件の付与率が2023年以前の100\%から2026年56.1\%へ低下し，2025年公開分の37.3\%をNVD自身が解析対象外と明示していた．
ただし付与率は検知精度を予測しない．
入力データソースのみを変えたDBで10環境を検知すると，NVDのみでの未検知率はWindows Server 2022の1.3\%からサポート終了版FortiOSの68.8\%まで開き，後者の93.5\%は組込みOSS部品のCVEであった．
VulnCheckはEdgeの未検知を96.2\%から0.4\%へ下げる一方，Windowsでは過剰検知率70.6\%を生む．
一次データソースが常に優るわけでもない．
どの供給源を使うべきかは製品ごとに異なる．
本稿はその判断に要る測定と，一次データソースをLLMで再現可能に構造化する方式を示す．
\end{abstract}

\begin{eabstract}
We develop Vuls, an open-source vulnerability scanner, and its database.
Given the CVE surge, we ask where a scanner should get its detection conditions.
Across all 353,704 non-rejected entries of NVD and VulnCheck NVD++, NVD's CPE applicability coverage fell from 100\% up to 2023 to 56.1\% in 2026, and 37.3\% of 2025 entries are marked Deferred.
Coverage, however, does not predict detection accuracy.
Across ten environments scanned with databases differing only in input source, the miss rate under NVD alone ranges from 1.3\% on Windows Server 2022 to 68.8\% on an end-of-life FortiOS, 93.5\% of the latter being embedded OSS components.
VulnCheck cuts Microsoft Edge's miss rate from 96.2\% to 0.4\% yet yields a 70.6\% false-positive rate on Windows.
Nor is the primary source always better.
Which source to use differs by product.
We report the measurements that decision needs and a reproducible LLM-assisted method for structuring primary sources.
\end{eabstract}
